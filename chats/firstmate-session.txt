  There are 19 small commits so far, each named for a decision, for example
  "Unify the enqueue rule and the loop rule into one condition" and "Cost the
  6-hour outage, and order recovery so it cannot destroy an edit". That history
  shows the thinking developing, which Tequity asked for.

  The design in brief:
  - Each field syncs on its own, not the whole record. Every field carries an
    ordering key: the time of the change, then a fixed tie-break between
    Salesforce and the portal, then the event id. The highest key is the current
    value.
    - On a webhook, the time is Salesforce's occurredAt.
    - On a portal save, it's the database clock at commit.
  - Two processes. A webhook receiver writes each incoming change in a single
    database transaction and only answers Salesforce after it's saved. A
    separate sync worker sends portal changes to Salesforce under a rate limit.
    The two never call each other; they only share the database.
  - One condition drives everything outbound: we call Salesforce only when what
    we believe Salesforce holds differs from our current value. That one
    condition covers the loop rule: when our own write comes back, the two
    values match, so nothing is sent again.
  - Duplicates: each event id is recorded in the same transaction that applies
    it, so a second copy changes nothing.
  - Out of order: an older change never becomes current but stays in the history
    with who made it and when.
  - The 6-hour outage:
    - Pending changes are saved in the same transaction as the edit, so they
      survive a restart.
    - On recovery, we first pull what changed in Salesforce, then send our
      queue. Sending first could overwrite Salesforce edits we hadn't seen.
  - Numbers: we run at 70 of the 100 allowed calls per second. A 6-hour outage
    leaves about 15,000 calls to Salesforce, which takes about 6.3 minutes to
    catch up end to end. Normal sync takes about 6 seconds against the 30-second
    limit. I checked the outage arithmetic and it adds up.

  1. It's far too long. It runs to about 18,000 words, and Tequity asked for "a
